- 근거 자료: [docs/data-inventory.md](data-inventory.md) (2부, PR #114), [docs/launch-check-2026-10-16.md](launch-check-2026-10-16.md) (1부)
- 이 문서의 어떤 내용도 코드·문구·설정·법률 문서로 반영되지 않았다. 각 항목은 소유자 승인 후 별도 PR로 진행한다.

## 1. AI 사용 안내

### 1.1 실제 AI 생성 범위 (2부 §7 기준)

| 구분 | 무엇 | AI 여부 |
|---|---|---|
| 공개 자료 카드 | 제목, 사실, 왜 중요한가, 할 일, 기간 (영·한 동시 생성) | **AI 생성** (Perplexity Agent API, 웹 검색 결과 기반) |
| 근거 요약 | 기회·마찰·불확실 문장, 종합 함의 | **AI 생성**. 카드가 일부 제외되면 고정 문장으로 교체 |
| 템플릿 속 인용 | 발견·확인 항목·계속 조건·경로 문장 안의 따옴표 구절 | 고정 템플릿 + **AI 문장 일부 인용** |
| 근거 방향·신뢰도 | supportive/caution, low/medium/high | **AI 선택값**. 모든 주제가 확인되면 `externalValidation`(시장 근거) 단계에 반영 |
| JEV 보조 판단 | low/medium/high 라벨 5개 | AI 선택값 (설명 문장은 고정 문자열) |
| 현재 판단, 안전 여유, 경로 조정, 판단이 바뀌는 조건, 7개 지표 | 규칙 엔진과 고정 템플릿 | **AI 아님** |
| 결정 유형·지역·검색 대상 추론, 용어집 번역 | 정규식·용어 표 | **AI 아님** |

이 범위를 벗어나는 표현(예: "이 분석은 AI가 작성했습니다", "AI가 판단합니다")은 사실과 다르다. 반대로 "AI를 쓰지 않습니다"도 사실과 다르다.

### 1.2 법령 검토 요약 (확인 날짜 2026-10-16, 공식 출처는 연구 자료 참조)

| 항목 | 공식 자료에서 확인한 내용 | AMC 적용 여부 |
|---|---|---|
| 인공지능기본법 시행 | 2026-01-22 시행 (law.go.kr, 법률 제21311호) | — |
| 제31조① 사전 고지 | 생성형·고영향 AI를 이용한 제품·서비스 제공 시 이용자에게 사전 고지 | **확인 필요**: AMC가 제2조7호나목 "이용사업자"(타사 AI를 이용해 서비스 제공)에 해당하는지. API 이용·무료 서비스에 대한 공식 해석은 찾지 못함 |
| 제31조② 결과물 표시 | 생성형 AI 결과물임을 표시 | **확인 필요**: 공개 자료 카드가 "생성형 AI 결과물"에 해당하는지 |
| 시행령 제23조 | 화면 고지 또는 약관 기재, 사람이 인식 가능한 방식 또는 기계 판독 + 안내. AI 이용이 명백한 경우 등 예외 | 방식 선택 근거 |
| 제재 | 31① 위반만 과태료(법 43①1, 최대 3천만원). 과태료 계도기간은 과기정통부 정책(최소 1년, 법령 아님) | 계도기간을 의무 면제로 해석하지 않음 |
| 과기정통부 가이드라인 | 원문 미확인. 보도상 서비스 내 표시는 UI 안내, 다운로드·공유 결과물은 결과물 자체 표시 | **원문 확인 필요** (PDF 리포트가 "다운로드 결과물"에 해당할 수 있음) |
| EU AI Act 제50조 | 2026-08-02 적용. 50(2) 표시 의무는 2026-08-02 이전 출시 시스템에 한해 2026-12-02로 유예(Reg. 2026/1744) | **확인 필요**: AMC가 EU에서 "provider/deployer"인지. 집행위 가이드라인(C(2026) 5054)은 EU에서 결과물이 쓰이면 역외 제공자도 포함될 수 있다고 하나, 우연한 사용만으로는 아니라고 함. 영어 UI의 EU 접근 가능성만으로 단정하지 않음 |
| 50(1) 상호작용 고지 | AI와 직접 상호작용하는 시스템 | AMC는 대화형이 아님 → 해당 가능성 낮음, 그러나 판단은 법률 검토 |
| 50(2) 기계 판독 표시 | 합성 텍스트 등 출력의 기계 판독 표시 (제공자 의무) | AMC가 제공자인지에 따라 다름. Perplexity가 1차 제공자 |

법률 검토가 필요한 쟁점(구현으로 해결되지 않음): 이용사업자 해당 여부, 카드가 생성형 AI 결과물인지, PDF가 "외부 공유 결과물"인지, EU 적용 범위, 표시 방식이 시행령 제23조의 어느 방식을 충족하는지.

### 1.3 위치별 UI 제안 (사전 고지와 결과물 표시 구분)

**(가) 분석 시작 전 화면 — 사전 고지**
- 목적: 외부 AI 검색이 쓰인다는 사실과 범위를 시작 전에 알림.
- 노출 시점: 시작 화면 동의 영역 위, 현재 `privacy` 안내 문장 자리.
- 배치: 별도 한 줄 블록 "AI·외부 검색 사용 안내" + 펼침 링크.
- KO: `공개 자료 검색에는 외부 AI 검색 서비스를 씁니다. 결과 화면의 ‘공개 자료’ 카드 문장은 이 서비스가 출처를 바탕으로 쓴 것이며, 현재 판단·안전 여유 등 구조 분석은 allofmycareer의 고정 규칙으로 계산합니다.`
- EN: `Public-source search uses an outside AI search service. The sentences on the ‘public sources’ cards are written by that service from the cited pages; the structural reading, safety margin and other analysis are calculated by allofmycareer's fixed rules.`
- 주의: 현재 "검색 대상만 씁니다" 문구(`AmcInteractiveV2.tsx:1079`)와 충돌하지 않게 그 문구 수정과 함께 검토(2부 §9).

**(나) 결과 대시보드 — 결과물 표시**
- 목적: 화면의 어느 문장이 AI 생성인지 구분.
- 배치: 공개 자료 카드 묶음 머리에 작은 표지 `AI 작성 · 출처 기반` / `AI-written from cited sources`, 각 카드 출처 줄 옆에 같은 표지(아이콘 없이 텍스트). 템플릿 안 따옴표 인용 구절은 "근거 N 인용" 표기로 출처 카드와 연결.
- 근거 요약(기회·마찰·불확실·함의)에도 같은 표지. 고정 문장으로 교체된 경우 표지를 빼고 "제외된 카드가 있어 요약을 생략" 문장 유지.
- 현재 판단 헤드라인에는 AI 표지를 붙이지 않는다(AI 생성이 아님). 대신 "시장 근거 단계는 공개 자료 카드의 방향·신뢰도를 반영합니다" 한 줄을 판단 근거 영역에 둔다 — 1부에서 확인된 "출처는 점수를 바꾸지 않습니다" 문구 충돌 해소와 함께.

**(다) PDF — 결과물 자체 표시**
- 목적: 화면 밖으로 나가는 결과물에도 표시가 남도록.
- 배치: 공개 자료 페이지 머리 `이 페이지의 카드 문장은 외부 AI 검색 서비스가 출처를 바탕으로 작성했습니다. 분석·판단은 고정 규칙으로 계산했습니다.` / EN 대응. 각 카드 출처 줄에 `AI 작성` 텍스트. 마지막 페이지에 AI 사용 범위 요약 + 면책 + 정책 링크(§2).
- 기계 판독 표시(메타데이터 등)는 50(2)·시행령 해석 확정 후 결정.

**AI 사용 안내 ≠ 분석의 한계 설명**: 한계("출처 접속 가능 ≠ 내용 검증", "결정 대행 아님")는 기존 문구 자리에 그대로 두고, AI 표지와 섞지 않는다.

## 2. `/privacy`, `/terms` 페이지 구조 (본문 미작성)

### 2.1 연결 위치

| 위치 | 현재 | 제안 |
|---|---|---|
| 시작 화면 동의 영역 (`AmcInteractiveV2.tsx:1158-1174`) | 링크 없음 | 서비스 동의 문구 끝에 "개인정보처리방침 / Privacy" 링크, 동의 영역 아래 한 줄에 "이용약관 / Terms" |
| 사이트 하단 (`:1456-1468`) | 면책 문장만, 리포트 단계에서 숨김 | 면책 문장 아래 "개인정보처리방침 · 이용약관 · 문의(report@allofmycareer.com)" 한 줄. 리포트 단계에서도 표시 |
| 리포트/PDF 마지막 페이지 | 법률 링크·면책 없음 | 면책 문장 + 두 문서의 URL을 텍스트로 인쇄 (PDF에서는 링크가 아닌 전체 URL) |
| 결론 추적 하단 | 면책만 | 하단 링크 한 줄 |

- 링크는 새 탭으로 열어 진행 중인 응답 상태(메모리)를 잃지 않게 한다. 현재 새로고침하면 모든 진행이 사라지므로(1부 A6) 같은 탭 이동은 피한다.

### 2.2 라우트와 렌더링

- 경로: `/privacy`, `/terms` (언어는 `?lang=ko|en`, 없으면 V2와 같은 규칙: 브라우저 언어).
- 현재는 SPA 기본 화면으로 처리되므로 `App.tsx`에 라우트 추가가 필요하다(구현 시).
- 정적 문서 페이지로 만들고 분석 상태·추적과 분리한다(추적 이벤트 없음, 동의 전에도 열람 가능).
- 인쇄 가능(브라우저 인쇄) 레이아웃.

### 2.3 페이지 골격

```
[상단] allofmycareer 로고 · KO/EN 전환 · "분석으로 돌아가기"
[문서 머리]
  제목: 개인정보처리방침 / Privacy Policy
  시행일: YYYY-MM-DD   버전: vN   (이전 버전 보기 링크)
[목차] 앵커 링크 (모바일에서는 접이식)
[본문 섹션 자리]  ← 본문은 법률 검토 후 작성. 섹션 이름만 둔다.
[하단] 문의처 · 이전 버전 목록 · 마지막 수정일
```

개인정보처리방침 섹션 자리 (법령상 필수 기재 항목은 3부 연구 자료 §5 참고, 내용은 data-inventory 기준으로 채우되 "확인 불가" 항목은 확정 전 비워 둠):
1. 처리 목적
2. 처리 항목 (서비스 운영 / 선택 연구 구분)
3. 보유·이용 기간과 파기 (현재 코드에 기간·삭제 경로 없음 → 정책 결정과 구현이 먼저 필요)
4. 제3자 제공 / 처리 위탁 / 국외 이전 (Perplexity, Vercel, DB 제공자, SMTP 제공자 — 위치는 콘솔 확인 후)
5. 정보주체의 권리와 행사 방법 (현재 행사 경로 없음 → 문의 메일 + 기록 ID 방식 설계 필요)
6. 안전성 확보 조치
7. 쿠키·브라우저 저장소 (sessionStorage 2종, 결론 추적 메모 localStorage, Google Fonts)
8. AI·외부 검색 이용 안내 (§1과 일관)
9. 개인정보 보호책임자·문의처
10. 변경 고지

이용약관 섹션 자리:
1. 서비스 성격 (조건부 구조 해석, 결정 대행·추천·자문 아님)
2. 이용 조건 (무료, 계정 없음)
3. 이용자 입력 시 유의사항 (기밀·민감정보 입력 금지)
4. 외부 공개 자료와 AI 생성 문장의 한계
5. 지식재산권 · 출처 링크
6. 책임의 제한
7. 서비스 변경·중단
8. 준거법·관할
9. 문의

### 2.4 한·영 전환과 버전

- 한국어가 기준본, 영어는 번역본이라는 표기 위치를 문서 머리에 둔다(어느 쪽이 우선하는지는 법률 검토 사항).
- 시행일·버전은 문서 머리와 하단에 모두 표시. 동의 기록에 문구 버전을 남기려면(§3) 이 버전 값과 맞춘다.
- 이전 버전은 `/privacy?v=N` 형태의 정적 보관본을 제안(구현 방식은 승인 후).

### 3.2 UI 제안

시작 화면 (현재 위치 유지, 서비스 이용을 막지 않음):

```
[✓] (필수) 서비스 동의 …  [개인정보처리방침]
[ ] (선택) 연구 동의 …    [자세히]
     └ 자세히: 무엇을(구간·유형·단계 등 식별 불가 항목), 왜(집계 연구), 얼마나(보유 기간),
              동의하지 않아도 결과는 같다는 문장, 철회 방법
```

- "선택" 표기를 체크박스 앞에 두고, 동의하지 않아도 결과가 같다는 문장을 같은 줄에 둔다.
- 결과 화면 하단(피드백 영역 옆)에 "연구 동의 변경" 작은 링크: 현재 상태 표시 + 토글. 변경 시 `research_use_consent` 갱신 이벤트를 보낸다(새 이벤트 타입 또는 기존 패치 — DB 계약 변경 여부는 승인 사항).
- 리포트 마지막 페이지에 기록 ID와 "철회·삭제 요청: report@allofmycareer.com, 기록 ID 기재" 안내.

### 3.3 동의 기록 방식 (선택지, 스키마 변경 여부 표시)

| 안 | 내용 | 스키마 변경 |
|---|---|---|
| A | `usage_events`에 `consent_recorded` 이벤트 추가(메타데이터: 동의 종류, 값, 문구 버전) | 이벤트 타입 CHECK 변경 필요(마이그레이션) |
| B | `submissions`에 `research_consent_at`, `consent_text_version` 컬럼 추가 | 컬럼 추가 |
| C | 기존 `structural_output_json`에 문구 버전 키 추가(투영 허용 목록 확장) | 스키마 변경 없음, 투영 코드 변경 |

- 철회는 A/B 모두 "철회 이벤트/시각" 기록이 필요하다. 삭제 요청 처리는 운영 절차(관리자 도구에 삭제 기능 없음)부터 정해야 한다.
- 어떤 안이든 DB 스키마·개인정보 투영 변경이므로 승인 대상(인수인계 §12).

## 4. 검색 API 요청 제한

### 4.1 현재 제한 (계층별 구분)

| 계층 | 확인한 내용 | 근거 |
|---|---|---|
| 앱 | `/api/amc/external-intelligence-v2`에 인증·동의·제출 ID 검사·IP별 제한이 **없음**. 본문 4096자, 필드 6개, 영역 7개 이하 검증만 있음. 요청 1건 = 최대 4개 주제 그룹 = 최대 4회 공급자 호출(각 429 재시도 최대 2회). 화면 1회 실행은 재시도 포함 최대 약 12회 | A (`api/amc/external-intelligence-v2.ts`, `externalIntelligenceV2Service.ts:358-404`, 1부 흐름 점검) |
| 앱 (JEV) | 요청 지문 기준 **전체 합산 6회** 상한 (제출별 아님, 버그로 보임) | A (`founderOpsStore.ts:210-211`) |
| 앱 (레거시) | `/api/amc/external-snapshot`도 제한 없음, 자유 텍스트 전송 | A |
| 플랫폼 (Vercel) | `vercel.json`에 방화벽 규칙 없음. 대시보드 WAF 규칙 존재 여부는 **확인 불가**(콘솔 미접근). 공식 문서: WAF 속도 제한은 모든 요금제, Hobby는 프로젝트당 규칙 1개. Hobby는 Spend Management 없음, 한도 초과 시 30일 잠금 가능 | A, C 없음, D |
| 공급자 (Perplexity) | 공식 문서: 사용 등급별 초당 요청 수(Tier 0=1 … Tier 4-5=33), 등급은 누적 충전액 기준. 선불 크레딧, 선택적 자동 충전, 잔액 0이면 401. 문서상 지출 상한 기능 없음. 이 계정의 등급·잔액·자동 충전 설정은 **확인 불가** | D, C 없음 |

- 과금은 "호출당"이며 총비용 상한이 아니다. 선불 잔액 소진(자동 충전 꺼진 경우)이 사실상의 상한이지만, 자동 충전 여부를 확인하지 못했으므로 상한이 있다고 단정하지 않는다.

### 4.2 앱 수준 제한안 비교 (구현하지 않음)

| | 안 A: 인스턴스 메모리 카운터 | 안 B: 기존 Postgres로 제출별 상한 | 안 C: 기존 Postgres로 서비스 전체 일일 예산 | 안 D: Vercel WAF 속도 제한 규칙 | 안 E: Upstash Redis 카운터 |
|---|---|---|---|---|---|
| 기준·위치 | IP별 N회/분, 함수 메모리 | 검색 요청에 유효한 제출 ID(동의 완료) 필수, 제출당 검색 실행 K회 이하. `usage_events`의 기존 `external_evidence_requested` 타입으로 서버가 기록·계수 (JEV 예약 방식과 동일 패턴) | 최근 24시간 공급자 호출 수가 상한 초과 시 검색 차단, 구조 초안 안내 | 경로 `/api/amc/external-intelligence-v2`에 IP별 요청 수 규칙 | IP·제출별 슬라이딩 윈도 |
| 기존 인프라 | 있음 | 있음 (테이블·이벤트 타입 재사용, 스키마 변경 없음 — 단 서버가 이벤트를 쓰는 것은 계약 변경으로 승인 필요) | 있음 | 있음 (대시보드 설정) | 없음 (마켓플레이스 신규 연결) |
| 난이도 | 낮음 | 중간 | 낮음~중간 | 낮음 (설정) | 중간 |
| 추가 비용 | 없음 | DB 쓰기 증가 (제공자 요금 구조는 확인 불가) | 같음 | 공식 문서상 Hobby 포함량 있음, 초과분 과금 — 계정 상태 확인 불가 | 무료 등급 존재, 초과·요금제는 불확실. **신규 서비스 가입은 이번 범위 밖** |
| 장점 | 즉시 가능 | 정상 고객 흐름과 정확히 맞물림, 동의 없는 직접 호출 차단 | 비용 폭주의 최후 차단 | 함수 실행 전 차단 → 함수·공급자 비용 모두 절감 | 정확한 분산 카운트 |
| 단점 | 서버리스에서 인스턴스마다 따로 셈 → **서비스 전체 상한을 보장하지 못함** | 제출 ID는 `/ops/track`로 누구나 새로 만들 수 있음 → 단독으로는 우회 가능 | 상한 도달 시 정상 고객도 검색 불가 | Hobby 규칙 1개, 지역별 카운터, IP 기반 | 외부 의존 추가 |
| 다중 인스턴스 한계 | 큼 | 없음 (DB가 단일 기준) | 없음 | 지역별 카운터 | 없음 |
| 정상 재시도 영향 | 낮음 | K를 "실행 수"로 세면 재시도·주제별 재검색까지 허용 가능 | 상한 근처에서 큼 | 같은 IP(회사망 등) 공유 시 오탐 | 낮음 |
| 우회·남는 위험 | 여러 인스턴스·IP | 제출 대량 생성 → 안 C 또는 D와 병행 필요 | 없음 (비용 측면) | IP 변경 | IP·제출 대량 생성 |

**권고(승인 대기)**: B + C 조합을 앱에 두고, 가능하면 D를 플랫폼에 추가. B는 정상 흐름(동의 → 시작 → 검색)을 강제하고, C는 비용 상한을 서비스 전체 기준으로 보장한다. A 단독은 서버리스에서 상한을 보장하지 않으므로 권하지 않는다. JEV 전체 합산 6회 버그는 별도 수정안으로 다룬다.

검토 시 함께 결정할 것: K와 일일 상한 값(현재 1회 실행 최대 약 12회 호출 기준), 상한 도달 시 고객 문구, Perplexity 자동 충전 설정 확인(소유자), Hobby 요금제의 상업적 이용 제한 해당 여부(소유자·법률 검토 — 공식 문서상 Hobby는 비상업 개인 용도).
