# V2 self-diagnostic input mapping (Task 060B.1)

This is an input and display map, not a new assessment model. Each case uses the same five card roles with case-specific questions and evidence examples. A card's evidence-status answer is a session-only self-report; it never sets a band, verifies an external fact, or enters the provider request. The customer selects each existing structural band separately. The progress count is completed card inputs, not readiness or probability.

The V2 step numbers above are not canonical question numbers. The canonical current-case adapter uses selections 17, 19, 20, 21, 23, and 25 by **field meaning**, independently of the V2 step index. The canonical report's FIFWM factor scores come from distinct `Q18_score`–`Q22_score` inputs in `src/report_payload_builder.py`. The five self-check cards do not set those factors. A separate, optional set of the original role/organization questions now appears within the readiness step when a customer has a specific target organization and role. Finance, readiness, support and self-check status never substitute for these answers.

The five roles are adapted to each of the nine existing case types. Their examples are prompts for what a person might verify, not new thresholds or proof of verification. The six structural bands, their original labels and the core analysis functions stay unchanged.

## Canonical FIFWM audit (not the V2 step numbers)

The authority is `src/intake_parser.py` for the original question and `src/engine.py` for the original value-to-score map. `src/report_payload_builder.py` maps the resulting `Q*_score` into the five factor fields. The V2 cards above do **not** ask these exact questions or collect these exact choices, even when a V2 selection happens to share a number. In particular, `optionBSupport` does not answer whether a manager or senior colleague in the target team actively sponsors the customer.

`manus-ui/scripts/generate_fifwm_rules.py` imports the unchanged original Python questions, `map_q18`–`map_q22` functions and report field resolver. It executes every allowed `Literal` choice and writes `manus-ui/client/src/data/generated/fifwm-rules.json` with the 15 results, original questions, output fields and source SHA-256 values. Regenerate with `python3 manus-ui/scripts/generate_fifwm_rules.py`; verify with `python3 manus-ui/scripts/generate_fifwm_rules.py --check`. The browser only looks up exact choices in this generated artifact, then passes the resulting in-memory report fields through the existing `buildFifwmFromReportPayload` adapter. A missing, null, unsure, inapplicable or invalid answer is omitted and remains unassessed; no score is inferred from a card, prose, or public source. The 243 complete combinations are compared against live Python execution in the web regression test.

The question set is offered only for Industry Transition, Role Upgrade / Downgrade, and Corporate Stay vs Exit, and only after the customer confirms a specific target organization and role. Otherwise all five factors remain unassessed. Choices are self-reported and session-only. They are not added to the public search request, Founder Ops payload, local storage or a server. Public evidence cannot validate personal sponsor, reporting line or workflow experience. Dashboard, report and simulator consume the same `buildV2Input` result; scenario overrides retain the baseline FIFWM inputs.
