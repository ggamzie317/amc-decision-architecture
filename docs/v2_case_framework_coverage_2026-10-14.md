# AMC V2 case-type coverage (read-only audit, branch claude/v2-launch-hardening)

Paths relative to `manus-ui/`. Case list: `shared/interactivePrivacy.ts:10-20`.

## Shared mechanics (apply to every case)

- **FIFWM gate**: `v2CanAskCanonicalFifwm` = Industry Transition, Role Upgrade/Downgrade, Corporate Stay vs Exit only (`client/src/data/v2CanonicalFifwm.ts:22-26`). Scores come only from canonical Q18-22 when `targetRoleStatus === "known"` and at least 1 exact choice (`:75-91`). Otherwise `buildUnavailableFifwm` sets every score to null (`amcProductApplicationV3.ts:180-185`). The UI card appears only for the 3 eligible cases (`AmcInteractiveV2.tsx:495-547`). Analysis status for null = "미확인 / Not established" (`amcV2Analysis.ts:706-714`). Scope note: eligible = "original five questions assess a known org/role"; ineligible = "do not apply ... unassessed" (`amcV2Analysis.ts:865-869`; `V2AnalysisView.tsx:281-289`).
- **Unknown in scoring**: `strengthScore.unknown = 1` (same as developing), `riskPenalty/loadPenalty/missingPenalty.unknown = 1` (same as moderate/material) (`amcProductApplicationV3.ts:187-190`). No FIFWM scores means `fifwmSupport = 1` (`:221`). `missingPointImpact` is always unknown in V2, a fixed penalty of 1 (`amcCurrentCaseStructuralSignals.ts:78`). Without live evidence, `externalValidation` is always unknown (`:42-43`). If every input is unknown: support = 1+2+2+1+1+1-1-1-1 = **5, which gives "validate" (Preserve and Validate / KO "현재 계획 유지")** (`:232`; KO relabel in `v2ReportPresentation.ts:109-118`).
- **Unknown display**: band label unknown = "Not Yet Established / 아직 확인되지 않음" (`v2Language.ts:129`). The safety ordinal shows "?" with level null (`amcV2Analysis.ts:716-722,770-781`; `V2AnalysisView.tsx:341-351`). FIFWM null shows as "미확인". **No customer string in the V2 path renders unknown as "Moderate/보통/중간."** "보통" appears only for an explicitly chosen `moderate` (`v2Language.ts:131`). "중간" appears only in "중간 경로" (intermediate route), the pathway play (`amcProductApplicationV3.ts:337`, `v2ReportPresentation.ts:133,138`), and is not a level.
- **Posture caveat**: `postureEvidenceCoverage` (limited/partial/stronger, `amcProductApplicationV3.ts:211-217`) is not rendered in any V2 customer component. Only `amcFounderOpsDerived.ts:29` uses it. The posture shows as an h1 (`V2Dashboard.tsx:282`, `V2Report.tsx:278`). The only caveat is the "Structural draft" tag when evidence is not live/demo (`V2Dashboard.tsx:258-280`).
- **Changing families** (`amcProductApplicationV3.ts:313-343`): role-scope if roleScopeEligible AND any known trigger. ELSE pathway if pathwayEligible AND (external weak/developing OR reversibility weak/developing). ELSE parallel-validation if external weak/developing (this needs **live** evidence, because external is unknown otherwise). resource if safety weak/developing OR downside high. timing if reversibility weak/developing. Max 3. If every input is unknown, **no plays for any case** (Decision Map shows "Conditions unresolved · no play derived", `V2AnalysisView.tsx:36-38`).
- **Evidence areas** (`shared/externalIntelligenceV2Request.ts:12-58`): career set = hiringDemand, roleDemand, compensation, requiredSkills, industryDirection, geography, visaMobility. Entrepreneur set = customerDemand, competition, pricing, marketGrowth, distribution, barriers, regulation. Education set = programOutcomes, employmentRelevance, researchRelevance, opportunityCost, funding, geographyMobility. Defaults: Entrepreneurship = 4 explicit, MBA = programOutcomes, employmentRelevance, funding, opportunityCost (`:55`), Industry = hiringDemand, roleDemand, requiredSkills, compensation (`:56`). All others use `slice(0,3)` = **hiringDemand, roleDemand, compensation** (`:57`). The UI chip options mirror these (`amcV2Model.ts:182-188`). Server search guidance is case-specific only for Ent/Industry/MBA, and generic otherwise (`server/externalIntelligenceV2Service.ts:172-178`).
- **Self-check cards**: one template for all cases with 4 case-specific slots (publicTarget/goal/cost/evidence) (`v2SelfDiagnostic.ts:19-74, 87-105`). The readiness/financial/recovery/capacity "example" lines are identical across cases.
- **Missing point**: case-specific for all 9 (`amcV2Presentation.ts:8-72`). **Next test**: KO case-specific for all 9 (`amcV2Presentation.ts:112-123`). EN comes from core `casePresentations[*].nextTest`, case-specific for all 9 (`amcProductApplicationV3.ts:261-306`).
- **Analysis profile** (topic/question/action/output/advance): case-specific for all 9 (`amcV2Analysis.ts:36-208`), plus an `academic` override for General when the text matches professor/lecturer etc. (`:209-238`). These are generic for every case: targetScope except Ent/MBA/Industry (`:362-368`), personalUnknown except Ent (`:369-371`), safety/readiness/capacity readings, boundary, pause, the 30/60/90 stage titles/actions ("Compare requirements with current evidence", "Test actual workload...") (`:868-920`), and the `buildV2Input.plan` (`amcV2Model.ts:407-426`).
- **Switch candidate default external label**: customerDemand (Ent), programOutcomes (MBA), otherwise **roleDemand** (`amcV2Model.ts:277-282`).
- **Public search target label/placeholder** in the UI: case-specific for Ent/Industry/MBA only, and generic otherwise (`AmcInteractiveV2.tsx:443-464`).

## Gaps: generic/template-only content

1. **Role Upgrade / Downgrade gets exit-framed role-scope copy.** It reads "before treating departure as necessary" and "Exit decision → role redesign test" / "퇴사 결정 → 역할 재설계 검증" (`amcProductApplicationV3.ts:336`). The KO `koreanPlayText` has no mapping for "퇴사 결정 → 역할 재설계 검증", so the raw text shows (`v2ReportPresentation.ts:131-141`).
2. **Overseas Relocation** gets default evidence areas hiringDemand/roleDemand/compensation, with no geography/visaMobility default (`externalIntelligenceV2Request.ts:57`). It has no case-specific search guidance (`externalIntelligenceV2Service.ts:178`), a generic search-target label (`AmcInteractiveV2.tsx:452-456`), and the switch label defaults to "Role demand" (`amcV2Model.ts:282`).
3. **Burnout / Family / General / Corporate / Role** all get the same three career defaults. Burnout and Family have no area that matches their missing point (recovery, care/schedule).
4. **Entrepreneurship, Burnout, Family and General have no case-specific Changing family.** Without live evidence, only resource and timing can appear, and none appear when bands are unknown.
5. The **30/60/90 stage titles and pause text** use one shared template with requirements/work-sample wording (`amcV2Analysis.ts:803-806, 868-920`). This fits poorly for Burnout and Family. `buildV2Input.plan` is generic for all cases (`amcV2Model.ts:407-426`).
6. **Self-check examples** for readiness/financial/recovery/capacity are identical across cases (`v2SelfDiagnostic.ts:93-96, 100-103`). Only the question nouns vary.
7. targetScope is generic for 6 cases and personalUnknown is generic for 8 (`amcV2Analysis.ts:362-371`). The pathway play copy ("intermediate route before full conversion") is the same for MBA, Industry and Overseas.

## Places where unknown may read as a confirmed middle level

- No V2 customer text labels unknown as "Moderate/보통/중간" (verified in `v2Language.ts`, `amcV2Analysis.ts` safety/factors, `V2AnalysisView.tsx`).
- **Implicit equivalence**: unknown is scored exactly like developing/moderate/material (`amcProductApplicationV3.ts:187-190`), and missing FIFWM equals 1 (`:221`). As a result, an all-unknown case receives a definite posture "Preserve and Validate / 현재 계획 유지" shown as an h1. `postureEvidenceCoverage = "limited"` is never shown to the customer. The "Structural draft" tag reflects only the evidence phase, not unknown bands (`V2Dashboard.tsx:258-282`).
- The KO posture sentence "지금 구조는 이 순서를 더 뒷받침합니다" (`v2ReportPresentation.ts:113-114`) asserts support even when it rests on neutral defaults.
- Simulator/sensitivity: switching a band between unknown and developing/moderate produces no posture change (follows from the scoring). How V2Simulator words a "no change" result was **unverified**.

## Items needing a product decision (no score/weight/boundary changes proposed)

- Whether the 6 non-FIFWM cases should get their own structure questions (for example Overseas destination employer, MBA program, startup channel), or stay explicitly "unassessed".
- Whether Overseas defaults should include geography/visaMobility, and whether Burnout/Family need new evidence areas (workload norms, leave policy, care availability). These need new allowlist entries plus server guidance.
- Role-scope copy for Role Upgrade/Downgrade (a non-exit wording), and whether Entrepreneurship/Burnout/Family/General should have a case-specific Changing family (this is a new rule).
- Whether to show `postureEvidenceCoverage` or an "inputs mostly unknown" caveat next to the posture.
- Case-specific 30/60/90 stages/pause text for Burnout/Family/Overseas.
